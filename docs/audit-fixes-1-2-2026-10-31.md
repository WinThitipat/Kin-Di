## การทดสอบ

- Production build ผ่าน ก่อนแก้ whitespace ในโค้ดเพิ่มเติมเท่านั้น
- verify-delete-dialog-pending.cjs: คำขอค้าง, ปิดด้วยยกเลิก/X/Esc, signal ถูก abort, response สำเร็จเก่าหลังเปิดใหม่ไม่ปิด dialog หรือลบแถวผิดจังหวะ, PIN จำลองผิดแล้วลองใหม่, timeout 25 วินาทีคืนช่อง PIN และล้างค่า, ลบสำเร็จผ่าน mock
- verify-community-field-errors.cjs: ส่งฟอร์มว่างแล้วตรวจ error ชื่อ คำอธิบาย URL และรูป ตรวจ ID ที่ aria-describedby ชี้ว่ามีข้อความจริง ตรวจ focus ช่องแรก URL ผิด กลุ่มมื้ออาหารว่าง วัตถุดิบว่าง ข้อความเพิ่มวัตถุดิบที่ยังไม่กดเพิ่ม ล้าง error หลังแก้ และไปถึงหน้าตรวจสอบได้
- verify-community-steps.cjs: validation, เดินฟอร์ม 4 ขั้น, ย้อนกลับคงข้อมูล, สลับแท็บ, review, save/reset และกลับเข้าแก้ไข ผ่านทั้ง mobile touch และ desktop
- ไม่พบ page error หรือ horizontal overflow ในกรณีที่เทสระบุ
- ตรวจภาพ field-errors-390.png แล้ว ข้อความ error อยู่ใกล้ช่องและไม่ตัดขอบ ภาพอยู่ใน artifacts/audit-fixes/

## ข้อจำกัด

การ abort/timeout ฝั่ง browser ไม่รับประกันว่าเซิร์ฟเวอร์ยังไม่ได้ลบ จึงเปลี่ยนข้อความจากการยืนยันว่าเมนูยังอยู่ เป็นให้ตรวจสอบรายการก่อนลองใหม่ และแสดงคำเตือนระหว่างรอ

ใช้ Chrome และ viewport จำลอง ไม่ใช่โทรศัพท์จริงทุกเครื่อง ยังไม่ได้ฟังผลด้วย screen reader จริง การตรวจ ARIA เป็นการตรวจ attribute และความสัมพันธ์ใน DOM ไม่ใช่การรับรอง WCAG ทั้งเว็บ

ทุกการบันทึก/ลบใน regression ใช้ข้อมูลจำลอง ไม่ได้เขียนหรือลบสูตรจริงและไม่ได้ใช้ PIN จริง การทดสอบนี้ไม่พิสูจน์พฤติกรรม backend หากธุรกรรมถูก commit ก่อน browser ยกเลิก

ข้ออื่นใน audit เดิม เช่น metadata ไพ่ 10px, ขอบ control, เป้ากดตู้เย็น, loading status หน้าสูตร และ metadata/favicon ยังไม่ได้แก้ในรอบนี้
